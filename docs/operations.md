# دليل تشغيل متجر GameBoss Q8

هذا الدليل لصاحب المتجر ولمن يساعده في التحديثات. الأقسام 1 إلى 4 تكفي صاحب المتجر، وبقية الأقسام فيها الخطوات التقنية لمن ينفّذ التحديث.

---

## 1. كيف يعمل المتجر؟

- المتجر موقع ثابت (صفحات جاهزة) مستضاف مجاناً على **GitHub Pages** على الرابط:
  `https://oalsoos13-crypto.github.io/gamebossq8-store/` (العربية)، و`…/gamebossq8-store/en/` (الإنجليزية).
- لا توجد قاعدة بيانات ولا لوحة تحكم ولا كلمات مرور على الموقع، فلا يوجد ما يمكن اختراقه أو ما يحتاج صيانة يومية.
- **الطلبات تصلك على واتساب** (97937556) برسالة جاهزة فيها: رقم الطلب (مثل `GB-261003-7KQ4`)، والمنتجات مع أرقامها (مثل `[#10736]`)، والمجموع، والعنوان، وطريقة الدفع.
  رقم المنتج بين الأقواس هو رقمه في ووردبريس، فتعرف المنتج مباشرة.
- كل بيانات المنتجات في ملف واحد: `data/catalog.json`. أي تعديل فيه ثم «نشر» يحدّث الموقع كله: الصفحات والأقسام والبحث والسلة.
- بعد النشر يظهر التحديث للزبائن خلال 1 إلى 10 دقائق تقريباً.

## 2. كيف أطلب تحديثاً؟

أرسل التعديل على واتساب لمن يدير الموقع، واذكر **رقم المنتج** (يظهر في رسالة الطلب، وفي آخر رابط المنتج، مثلاً `…/p/piva-ds5-adapter-10736/` رقمه 10736).

| ماذا تريد؟ | ماذا ترسل؟ |
|---|---|
| تغيير سعر | رقم المنتج + السعر الجديد (+ السعر قبل الخصم إن كان عليه عرض) |
| نفدت الكمية أو رجع المنتج | رقم المنتج + «نفد» أو «متوفر» |
| منتج جديد | الاسم بالعربي، والسعر، والقسم، و3 إلى 6 صور واضحة بخلفية بيضاء، ووصف قصير (اختياري) |
| حذف منتج | رقم المنتج (نفضّل جعله «غير متوفر» بدل حذفه، حتى لا ينكسر رابطه عند من شاركه) |
| تغييرات كثيرة | صدّر ملف CSV من ووردبريس (القسم 3) وأرسله |
| تفعيل رسوم التوصيل | الرسوم + حد التوصيل المجاني (انظر docs/owner-questions.md) |

## 3. تصدير ملف المنتجات من ووردبريس (WooCommerce)

ما دام ووردبريس يعمل، يمكنك إدارة المنتجات فيه كما اعتدت، ثم تصدير الملف:

1. ادخل لوحة ووردبريس ← **المنتجات** ← **تصدير** (Products ← Export).
2. اترك الخيارات كما هي: **كل الأعمدة**، و**كل أنواع المنتجات**، و**كل التصنيفات**.
3. لا تحتاج إلى تصدير «البيانات الوصفية المخصصة» (Custom meta).
4. اضغط **إنشاء ملف CSV**، وأرسل الملف الناتج.

الأداة تفهم الملف كما هو: تتجاهل النسخ الإنجليزية المكررة التي أنشأتها إضافة الترجمة، وتتجاهل المنتجات غير المنشورة، وتفهم الفاصلة العشرية مثل `16,5`.

## 4. أشياء مهمة قبل إلغاء استضافة ووردبريس ⚠️

صور المنتجات ما زالت تُحمَّل من `gamebossq8.com`. **إذا أُلغيت الاستضافة قبل نقل الصور ستختفي الصور من المتجر الجديد.**
لذلك قبل الإلغاء بأسبوع على الأقل:

1. نفّذ «نقل الصور» (القسم 8) ثم انشر.
2. تأكد أن صور المنتجات تظهر في الموقع الجديد.
3. صدّر ملف CSV أخيراً واحتفظ به نسخة احتياطية.
4. بعد ذلك يمكن إلغاء الاستضافة. وإن أردت استخدام الدومين `gamebossq8.com` للمتجر الجديد، فانظر القسم 12.

# الجزء التقني (لمن ينفّذ التحديث)

المتطلبات: Node.js 20 أو أحدث، وGit. لا يحتاج المشروع إلى `npm install` (لا توجد أي حزمة خارجية).

```bash
git clone https://github.com/oalsoos13-crypto/gamebossq8-store.git
cd gamebossq8-store
```

## 5. دورة التحديث المعتادة

```bash
# 1) عدّل data/catalog.json يدوياً، أو استورد ملف CSV (القسم 6)
# 2) ابنِ نسخة تجريبية في مجلد مؤقت وراجعها
node tools/build.mjs --out /tmp/gb-preview/gamebossq8-store
python3 -m http.server 8080 -d /tmp/gb-preview      # ثم افتح http://localhost:8080/gamebossq8-store/
# 3) الفحص الآلي (روابط، أخطاء، تجاوز العرض، السلة والطلب، إمكانية الوصول)
node tools/verify.mjs --out /tmp/gb-preview/gamebossq8-store
# 4) ابنِ في جذر المستودع (هذا ما ينشره GitHub Pages) ثم انشر
node tools/build.mjs
git add -A && git commit -m "تحديث الأسعار والتوفر" && git push
```

- GitHub Pages ينشر الفرع `main`، المجلد `/` (الجذر). كل `push` يبدأ النشر تلقائياً.
- البناء يحذف فقط الملفات التي أنشأها في المرة السابقة (يسجّلها في `.build-manifest.json`)، ولا يلمس `src/` أو `data/` أو `tools/` أو `docs/`.
- للتأكد من أن النشر وصل: افتح `…/gamebossq8-store/build.json` وقارن `publishId` بما طبعه البناء.

### تعديل يدوي سريع في `data/catalog.json`

| الحقل | المعنى |
|---|---|
| `priceFils` | السعر **بالفلس** (16.500 د.ك = `16500`) |
| `compareAtFils` | السعر قبل الخصم بالفلس، أو `null` إذا لم يكن على المنتج عرض. يجب أن يكون أكبر من `priceFils` |
| `availability` | `"in_stock"` متوفر، `"out_of_stock"` نفد، `"backorder"` طلب مسبق |
| `featured` | `true` ليظهر في «مختارات» |
| `category` | قسم المنتج: `mobile` `trigger` `tablet` `glove` `fan` `cable` `case` `headset` `stand` `accessory` `bag` `device` |
| `name.ar` / `name.en` | الاسم بالعربي والإنجليزي |
| `description.ar` / `description.en` | الوصف (نص عادي؛ السطر الذي يبدأ بـ `• ` يظهر نقطة). `en: null` يعرض الوصف العربي في الصفحة الإنجليزية |
| `sort` | الترتيب الافتراضي (الأصغر أولاً) |
| `slug` | جزء الرابط — **لا تغيّره** بعد النشر |
| `id` | رقم ووردبريس — **لا تغيّره** أبداً (السلة والطلبات تعتمد عليه) |

البناء يتحقق من البيانات ويرفض النشر عند وجود خطأ (مثل سعر صفر، أو سعر قبل الخصم أقل من السعر، أو قسم غير موجود).

## 6. استيراد ملف CSV من WooCommerce

```bash
node tools/import-csv.mjs ~/Downloads/wc-product-export.csv --dry-run   # يعرض التغييرات فقط
node tools/import-csv.mjs ~/Downloads/wc-product-export.csv             # يطبّقها على data/catalog.json
```

- **يُحدَّث من الملف:** الاسم العربي، والسعر، والسعر قبل الخصم، والتوفر، والصور، والوصف العربي، والماركة.
- **يبقى كما هو (تعديلاتك اليدوية محفوظة):** الرابط (`slug`)، والاسم والوصف بالإنجليزي، و«مميز»، والترتيب، والقسم.
  إذا اختلف القسم أو علامة «مميز» في ووردبريس، تظهر لك ملاحظة. لتطبيق قيمة ووردبريس استخدم:
  `--take-csv category,featured` (والخيارات الأخرى: `name-en` و`description-en`).
- **منتج جديد:** يُضاف باسم إنجليزي ورابط مولَّدين آلياً، ويظهر أولاً في الترتيب. راجع الاسم الإنجليزي قبل النشر.
- **منتج حُذف أو أُلغي نشره في ووردبريس:** يُحذف من المتجر. لإبقائه «غير متوفر» حتى لا ينكسر رابطه، أضف `--keep-removed`.
- خيارات أخرى: `--check` (يخرج بخطأ إذا وُجد أي فرق، ويفيد للتحقق)، و`--report diff.json`، و`--anomalies issues.json` (تعارض الأسعار، والمنتجات بلا صور…).
- الصور التي نُقلت إلى المتجر (القسم 8) تبقى محلية، ولا يعيدها الاستيراد إلى روابط ووردبريس.
- لتصحيح دائم لخطأ إملائي في اسم منتج: صحّحه في ووردبريس، أو أضفه إلى `NAME_AR_FIX` في `tools/import-csv.mjs`.

بعد الاستيراد: ابنِ وراجع وانشر (القسم 5).

## 7. تفعيل رسوم التوصيل المؤكدة

في `data/config.json`:

```json
"delivery": { "feeFils": 1500, "freeOverFils": 25000, "confirmed": true }
```

- ما دامت `confirmed: false` (الوضع الحالي) لا يذكر الموقع أي رسوم ولا توصيلاً مجانياً، ويكتب «التوصيل: يتأكد على واتساب».
- مع `confirmed: true` تُحسب الرسوم في السلة وصفحة الطلب والرسالة، ويظهر شريط «باقي لك … للتوصيل المجاني».
- للتجربة قبل التفعيل: `node tools/build.mjs --out /tmp/gb-preview/gamebossq8-store --set delivery.confirmed=true`

## 8. نقل صور المنتجات إلى المتجر (قبل إلغاء ووردبريس)

نفّذه على جهاز متصل بالإنترنت ويصل إلى `gamebossq8.com`:

```bash
node tools/mirror-images.mjs --dry-run     # يعرض عدد الصور وأماكن حفظها
node tools/mirror-images.mjs               # ينزّل الصور ويحدّث data/catalog.json
```

- تُحفظ الصور في `src/static/img/p/<رقم المنتج>/<1،2،3…>.<webp|jpg|png>`، وتتحول روابطها في الكتالوج إلى `img/p/…` (يضيف الموقع المسار الأساسي تلقائياً، فتستمر بالعمل بعد الانتقال إلى دومين خاص).
- يمكن إعادة التشغيل بأمان بعد أي انقطاع، فالصور المنزّلة سابقاً لا تُنزَّل مرة أخرى. الصور التي فشل تنزيلها تبقى على رابطها الأصلي، ويطبع السكربت قائمة بها.
- `src/static/img/p/sources.json` يسجل مصدر كل صورة.
- إذا تغيّر الـ DNS أثناء النقل: `--rewrite-origin https://gamebossq8.com=https://<IP أو الرابط المؤقت>`.
- يوجد حالياً نحو 700 صورة. بعد النقل: ابنِ، وافتح عدة صفحات منتجات، ثم انشر.
- لإضافة صور منتج جديد لاحقاً: ضع الملفات في `src/static/img/p/<id>/1.webp` وغيرها، واكتب في `images` القيم `"img/p/<id>/1.webp"` وهكذا (يُفضّل WebP مربع بعرض 1200 بكسل تقريباً وبحجم أقل من 300 كيلوبايت).

## 9. روابط إنستقرام وتيك توك (معرفة مصدر الزبون)

ضع في البايو رابطاً فيه `?src=`:

- إنستقرام: `https://oalsoos13-crypto.github.io/gamebossq8-store/?src=ig`
- تيك توك: `https://oalsoos13-crypto.github.io/gamebossq8-store/?src=tt`
- إعلان أو حملة: `?src=snap-oct` وأي اسم قصير آخر (ويُقبل `utm_source` أيضاً).

يحفظ الموقع أول مصدر للزائر مدة 30 يوماً، ويضيفه في آخر رسالة الطلب («المصدر: ig»)، فتعرف من أين جاءت كل طلبية.

## 10. الإحصاءات (اختياري)

الموقع لا يرسل أي إحصاءات حالياً. لتفعيل [GoatCounter](https://www.goatcounter.com) (مجاني وبدون كوكيز):
أنشئ حساباً (مثلاً `gamebossq8`)، ثم في `data/config.json`:

```json
"analytics": { "provider": "goatcounter", "code": "gamebossq8" }
```

بعد ذلك تُسجَّل الزيارات وأحداث مثل: إضافة إلى السلة، وفتح واتساب للطلب، والبحث بدون نتائج. وتتحدث صفحة الخصوصية تلقائياً لتذكر ذلك.

## 11. الطوارئ والتراجع

### التراجع عن تحديث خاطئ (Rollback)
```bash
git log --oneline -10            # اعثر على آخر نسخة سليمة
git revert <رقم-الـcommit-الخاطئ>  # ينشئ commit يلغي التغيير
git push
```
بعد الدفع يعود الموقع إلى حالته السابقة خلال دقائق. لا تستخدم `git push --force` على `main`.

### مفتاح إيقاف الـ Service Worker (Kill switch)
إذا علق الزبائن على نسخة قديمة أو معطوبة من الموقع بسبب التخزين المؤقت:
```bash
node tools/build.mjs --set pwa.killSwitch=true
git add -A && git commit -m "إيقاف service worker مؤقتاً" && git push
```
ينشر هذا ملف `sw.js` يحذف كل ذاكرة المتجر المؤقتة (الأسماء التي تبدأ بـ `gbq8-` فقط، لأن النطاق github.io مشترك مع مشاريع أخرى)، ثم يلغي تسجيل نفسه. بعد إصلاح المشكلة ابنِ وانشر بدون هذا الخيار ليعود التخزين المؤقت والعمل بدون اتصال.

### الموقع لا يتحدث؟
- انتظر 10 دقائق (ذاكرة GitHub Pages المؤقتة).
- تأكد من نجاح النشر في تبويب **Actions** أو **Settings ← Pages** في GitHub.
- قارن `publishId` في `…/build.json` بما طبعه البناء.
- يظهر للزائر الذي فتح الموقع سابقاً تنبيه «تحديث جديد متوفر — تحديث».

## 12. الانتقال إلى دومين خاص (مستقبلاً)

1. في `data/config.json` غيّر `"base": "/"` و`"origin": "https://gamebossq8.com"` (أو الدومين الجديد).
2. أضف ملف `CNAME` يحتوي اسم الدومين في `src/static/`، واضبط الدومين من **Settings ← Pages ← Custom domain**.
3. اضبط سجلات DNS حسب تعليمات GitHub، وفعّل **Enforce HTTPS**.
4. ابنِ وانشر. ملف `robots.txt` وخريطة الموقع يصبحان فعّالين لمحركات البحث على الدومين الخاص.
5. روابط ووردبريس القديمة (مثل `/product/…`) لا تعمل في المتجر الجديد، وتظهر لزائرها صفحة 404 فيها بحث وأقسام. أما روابط المتجر الجديد التي تغيّر جزء الاسم فيها، فتوجهها صفحة 404 تلقائياً إلى المنتج الصحيح ما دام الرابط ينتهي برقم المنتج.

ملاحظة: سلال الزبائن ومفضلاتهم محفوظة في متصفحاتهم حسب الدومين، فلا تنتقل عند تغيير الدومين.
